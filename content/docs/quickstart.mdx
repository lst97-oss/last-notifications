---
title: Quickstart
description: Create an app, publish a notification, and read it back from the inbox.
---

This walks through one publish and one read against a running server. Start the server first with [Self-hosting](/docs/self-hosting).

<Steps>
<Step>

### Create an app

Sign in to the dashboard and open `/dashboard/apps`. Create an app with a name and the origin of the site that will publish. The app's key is listed there. That key is the `appKey` in every URL below.

</Step>

<Step>

### Create a key

Open `/dashboard/api-keys` and create a key for your app. Keep **In-app** ticked. It grants `notifications:create` to publish and `tokens:create` to mint browser tokens. The key starts with `lnk_` and is shown once. Keep it on your server. See [Permissions](/docs/permissions) for what each feature adds.

</Step>

<Step>

### Publish a notification

Send the notification from your server with the key as a bearer token:

```bash
curl -X POST "https://notify.example.com/api/v1/apps/$APP_KEY/notifications" \
  -H "Authorization: Bearer $LNK_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "recipientKey": "user-42",
    "type": "comment.reply",
    "title": "New reply",
    "body": "Someone replied to your comment",
    "data": { "url": "https://app.example.com/thread/9" }
  }'
```

The response is `{ "data": { "id", "duplicate", "channels" } }`. The `channels` list shows which channels this notification was routed to.

</Step>

<Step>

### Mint a recipient token

Your server mints a short-lived token for the user whose inbox a browser will show. The same key does this, since In-app includes `tokens:create`. To keep publishing and minting apart, create a second key with only `tokens:create`, as described in [Permissions](/docs/permissions):

```bash
curl -X POST "https://notify.example.com/api/v1/apps/$APP_KEY/recipients/user-42/token" \
  -H "Authorization: Bearer $LNK_KEY"
```

Hand the returned `lrt_` token to the page. It expires after 15 minutes. See [Recipient tokens](/docs/recipient-tokens).

</Step>

<Step>

### Read the inbox

The browser reads the inbox with the recipient token:

```bash
curl "https://notify.example.com/api/v1/apps/$APP_KEY/inbox?order=desc&limit=20" \
  -H "Authorization: Bearer $LRT_TOKEN"
```

The page now has the notification, the unread count and the cursor it needs to stay live. See [Realtime](/docs/realtime).

</Step>
</Steps>

<Callout type="warn" title="Browser calls need a registered origin">
  Cross-origin requests from a browser are only answered for origins the app has registered. Register the site's origin on the app at `/dashboard/apps`. Your server-to-server calls above are not affected.
</Callout>
